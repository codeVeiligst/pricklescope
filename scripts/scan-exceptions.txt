# React Router 7.18.2, patched only in 8.3.0.
#
# The advisory is a CSRF bypass in RSC mode: a server action can execute before
# the framework returns 400. PrickleScope uses React Router declaratively in a
# Vite SPA — BrowserRouter, Routes, Link, useNavigate — with no data router, no
# server actions, and no RSC packages installed, so there is no code path that
# executes an action at all. CSRF on the real mutation surface is enforced by the
# API: a session-bound token compared with timingSafeEqual, plus an Origin match,
# neither of which involves the router.
#
# Not fixed because the fix is a major upgrade: react-router-dom is not published
# for v8, so it means migrating every import to react-router and taking v8's other
# breaking changes during a hardening milestone.
#
# Revisit when: the application adopts a data router, framework mode, or RSC — or
# at the next planned dependency upgrade, whichever comes first.

# Runtime base-image findings, reviewed 2026-08-12.
#
# An external audit (F6) found the scan reporting "clean" while pinned images
# carried Critical vulnerabilities upstream had already fixed. The policy treated
# "inherited from a base image" as "nothing we can do", which is true only when
# no fix exists. It now blocks an inherited High or Critical that has a published
# fix.
#
# Turning it on produced 30 findings. Acting on them showed the distinction that
# matters, and it is not the one the audit or I first assumed:
#
#   Trivy's "fixed version" means the *package* has a fix released. It does not
#   mean a *rebuilt image* exists to move to. Every pin here was already at the
#   newest digest its tag resolves to on 2026-08-12 — postgres 17.10-alpine,
#   questdb 9.4.3, grafana 13.1.3, caddy 2.11.4-alpine, node 24.19.0-alpine — so
#   for those there is no bump available and none of these can be closed by
#   pinning today.
#
# Telegraf was the exception and the proof: 1.39.3 existed, the pin moved, and
# all five of its findings went away, including the CVE-2026-49980 the audit
# named. Its entries are gone from this list rather than renewed.
#
# What to do with the rest: re-resolve the digests each tag points at. When a
# maintainer rebuilds, the digest moves under the same tag and the finding
# disappears — delete the entry then. This is the check:
#
#   docker buildx imagetools inspect postgres:17.10-alpine | grep Digest
#
# Do not add to this block for a finding a bump could clear. That is the case it
# exists to block.
# ---------------------------------------------------------------------------

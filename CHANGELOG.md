# Changelog

Notable changes to PrickleScope, in the format of
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning is explained
in [docs/releasing.md](docs/releasing.md).

Entries describe what an operator has to know. The commit list is generated by
the release workflow and is not repeated here.

## Unreleased

### Fixed

- **The Pipeline health dashboard had never had data.** It queried a table
  nothing wrote, so it drew an empty chart permanently. Collector health is now
  collected into `collector_health`, and the declared columns are the ones
  Telegraf actually emits rather than four invented ones.
- **Two tables grew without limit.** The bootstrap collector configuration ran
  the `internal` and `mem` inputs, whose tables the line protocol created
  implicitly — so the retention reconciler never expired them. Both inputs moved
  into the managed configuration under a table the controller owns.
  **Upgrading from 0.1.1 needs two one-off steps**, including recreating the
  collector container rather than restarting it: see
  [docs/upgrades.md](docs/upgrades.md).

### Removed

- `infra/questdb-backup.sh` and `infra/questdb-restore-test.sh`. They only ever
  worked against the development stack — they read the development environment
  file and reached QuestDB on a port production does not publish. Use
  `infra/backup.sh` and `infra/restore-test.sh`, which cover QuestDB along with
  PostgreSQL and Grafana in one consistent pass.

## 0.1.1 — 2026-08-10

Everything here was found by installing 0.1.0 the way a stranger would: a
fresh clone of the tag, in a directory of its own, following
[docs/deployment.md](docs/deployment.md) literally. The install worked. Six
things around it did not, and none of them could have been found by reading.

**If you are deploying for the first time, start here rather than at 0.1.0.**

### Fixed

- **The released images could not be used.** The Compose file fixed the image
  name to a local build, so every documented path built from source and the
  published images were unreachable. Set `PRICKLESCOPE_IMAGE_PREFIX` and start
  with `./scripts/prod-up.sh --no-build` to run them.
- **`--no-build` did not prevent a build.** It omitted `--build` rather than
  passing `--no-build`, and Compose builds any image it cannot find. An
  unreachable registry or a version that does not exist was quietly replaced by
  a local build of the checkout — running something other than what you asked
  for, under the name of the thing you asked for.
- **Backup did not work on a production host.** It defaulted to the development
  environment file, which production does not have, and issued the QuestDB
  checkpoint to a port that production deliberately does not publish. The
  metrics half of the backup was unreachable by construction on every deployment
  the script exists for. **If you deployed 0.1.0, your backups are incomplete —
  take a new one after upgrading and verify it with `./infra/restore-test.sh`.**
- **The verification step could not verify your deployment.** It required a file
  the documented steps never create and rebuilt the images it was meant to
  inspect. It now takes `--env-file` and `--no-build`.
- **A new installation reported the wrong version.** The example configuration
  shipped `1.0.0`, so a clean install of 0.1.0 called itself 1.0.0 in the API and
  the interface.
- **A failed image pull was reported as an unhealthy container**, which is true
  and useless. It now names the cause.
- Release notes are generated from this file instead of being written by hand in
  the workflow, and the entry is required by the release gate rather than
  discovered after the images have been published. The 0.1.0 signing step also
  failed on a registry path that must be lowercase; the image name is now derived
  once.

### Verified

On a live installation of these fixes: images pulled from the registry and both
containers reporting the published digests, 24 of 24 origin assertions with no
rebuild, backup of all three stores restored 8 of 8 in throwaway containers, and
a rollback from a version that does not exist that refused rather than
substituting — leaving every source, credential, and metric in place.

## 0.1.0 — 2026-08-09

The first release. **0.1.0, not 1.0.0.** Everything below works and has
been verified against a live stack, but three items in Milestone 8 are open —
alerting on the controller's own health, the accessibility audit, and task-based
usability testing. A `1.0.0` would claim those were done.

### Added

- **Sources, credentials, and polling profiles**, managed entirely in the browser.
  SNMP v2c and v3, with on-demand discovery that reads back what a device actually
  is. Sites form a cycle-safe tree of arbitrary depth.
- **Users and access.** Local accounts and OIDC with PKCE, three roles ordered
  viewer < operator < administrator, server-side sessions, and administrator
  self-lockout protection. OIDC is configured in the browser, not in a file.
- **Telegraf reconciliation.** The controller renders the collector configuration,
  publishes it atomically, keeps every revision, and can roll back to any of them.
- **QuestDB storage** with three retention tiers, materialized rollups, and
  reset-aware counter rates derived in the collector.
- **Native graphs**, drawn by the product with no third-party chrome, alongside
  provisioned Grafana dashboards that always carry at least the same panels.
- **Threshold alerting** with pending duration, hysteresis, and explicit No Data
  handling. Grafana evaluates; PrickleScope owns the rules.
- **Notifications** over HTTP only — a webhook, or email through a mail provider's
  API (Microsoft Graph, Gmail, SendGrid, Mailgun, Postmark, Nylas). No SMTP.
- **Drift detection.** Every reconciled engine reports whether what the controller
  would write matches what is running, by comparing content rather than
  timestamps, and one control applies them all.
- **A production deployment**: a Caddy gateway terminating TLS and serving the
  SPA, with `/grafana` routed through the API so the session is checked and the
  identity reconstructed. Nothing behind the gateway is published.
- **Backup and restore** for all three stores, with a restore test that proves a
  backup works rather than assuming it.
- **Operational tooling**: dependency and container scanning, static analysis and
  secret scanning with self-tests, documentation checks, and an SBOM per image.

### Security

Verified in a dedicated pass — 127 executable security assertions, an OWASP ASVS
5.0 and API Security Top 10 assessment, static analysis, secret scanning, and an
authenticated dynamic scan. See
[docs/security/verification.md](docs/security/verification.md).

That review found and fixed:

- **Critical** — a source name containing newlines escaped the TOML comment it was
  rendered into and injected a Telegraf `exec` input, letting any operator run
  commands on the collector host.
- **High** — an operator could redirect a mail-provider call and receive its API
  key; `/sync/apply` let an operator trigger three administrator-gated reconciles;
  a working AES-256 key shipped in the committed `.env.example` and was copied
  into every new `.env`.
- **Medium and low** — rate limiting reported itself as a server fault, the
  OpenAPI document was public, the storage-policy request accepted any field, and
  API responses were cacheable.

### Known limitations

- Single host. No clustering, and nothing beyond ~500 sources has been tested.
- SNMP and ICMP against network devices. No logs, traces, or APM.
- No bulk rotation of the credential encryption key; it is versioned and fails
  closed, but changing it means re-entering every stored secret.
- Jobs, audit events, and collector revisions accumulate without pruning.
- Mute timings and maintenance windows are not implemented.
- Telegraf's remote-write listener is unauthenticated and relies on the container
  network boundary.

[docs/security/threat-model.md](docs/security/threat-model.md) records the
accepted risks with the condition that would reopen each one.
